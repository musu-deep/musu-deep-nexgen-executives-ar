# ARAAK Access Fabric

يوثق هذا الملف نموذج الهوية والصلاحيات المؤسسية في مكتب الرئيس التنفيذي.

## دورة حياة الحساب

1. ينشئ مدير النظام دعوة للمستخدم من لوحة إدارة المستخدمين.
2. يتلقى المستخدم رابط تفعيل أحادي الاستخدام ومحدود الصلاحية.
3. يختار المستخدم كلمة مروره بنفسه؛ لا يراها مدير النظام.
4. يمكن لمدير النظام تعطيل الحساب أو إعادة إصدار الدعوة، ولا يمكنه استخراج كلمة المرور.
5. التسجيل العام ودليل الحسابات عبر معرف المجموعة متوقفان.

## نموذج قرار الوصول

يجمع المحرك بين:

- هوية المستخدم.
- قالب الدور والصلاحيات الذرية.
- النطاق التنظيمي أو المشروع أو المورد.
- عضوية مجموعات العمل.
- التفويضات المؤقتة.
- تصنيف المورد ومستوى تصريح المستخدم.
- السياسات السياقية مثل المصادقة الثنائية والحدود المالية.

## المجموعات

المجموعة ليست وسيلة تسجيل دخول ولا تكشف أسماء الحسابات. هي وعاء إداري لإسناد دور أو صلاحيات لعدد من المستخدمين داخل وحدة أو لجنة أو مشروع.

## الترحيل

تُحوَّل الأدوار الستة القديمة تلقائياً إلى قوالب أدوار نظامية، مع استمرار الحقول القديمة مؤقتاً للتوافق مع الوحدات التي لم تنتقل بعد إلى فحص الصلاحيات الذرية.

## التشغيل

- `ENABLE_DEMO_USERS=false` في التشغيل المؤسسي.
- `BOOTSTRAP_ADMIN_EMAIL=admin@araak.org` أو البريد الإداري المعتمد.
- `FRONTEND_URL` يجب أن يشير إلى رابط الواجهة المستخدمة في روابط الدعوات.
- `INVITE_TTL_HOURS=24` افتراضياً.

## المبدأ الحاكم

المنع هو الوضع الافتراضي، ومدير النظام يدير الهوية والسياسات ولا يُمنح تلقائياً الاطلاع على جميع الملفات التنفيذية الحساسة.
